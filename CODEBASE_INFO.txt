1. PROJECT OVERVIEW & CORE CONCEPT
--------------------------------------------------------------------------------
LumenPipe is an air-gapped, one-way optical file broadcast system:
- A laptop screen displays an animated N×N grid of high-speed QR "droplets".
- Smartphone cameras in a browser web page read and decode them in real-time.
- Luby Transform (LT) fountain codes reconstruct the original file incrementally.
- Zero radio frequency (RF) is used on the data channel: no Wi-Fi, no Bluetooth,
  no NFC, no pairing, no handshakes, and NO ACK/NACK (unidirectional).
- Broadcast model: A single screen stream serves unlimited phones simultaneously
  (each phone only needs line-of-sight to the screen).
- Rateless & order-free: Droplets carry random linear XOR combinations of source
  chunks. Droplets can arrive out of order; missed frames only cost time. Late
  joiners can start reading at any point and still decode the complete file.
- Integrity verified: Original file CRC32 is embedded in every droplet header.
  After GF(2) elimination and pako.inflate, CRC32 is strictly verified.
- Web-native PWA: No app store installation needed. Works offline once cached.

5. MATHEMATICAL & CODEC ARCHITECTURE
--------------------------------------------------------------------------------
A. Wire Format (Spec §4, src/lib/format.js):
   - Every packet starts with a 16-byte Little-Endian Header:
     [0..1]   sid            (uint16): Random Session ID
     [2..3]   seq            (uint16): Droplet sequence counter (for stats)
     [4..5]   K              (uint16): Total source chunks count
     [6..7]   chunkSize      (uint16): Chunk size in bytes (160 or 240)
     [8..11]  compressedLen  (uint32): Exact byte length of deflated payload
     [12..15] crc32          (uint32): IEEE CRC-32 of ORIGINAL (uncompressed) file
   - Followed immediately by payload of exactly `chunkSize` bytes.
   - Total packet size = 16 + chunkSize bytes (Plan A = 256 B, Plan B = 176 B).

B. LT Fountain Coding (Spec §6, src/lib/lt.js, encoder.js, decoder.js):
   - PRNG: Mulberry32 seeded with random 32-bit integer per droplet.
   - Robust Soliton Distribution:
     * Parameters: c = 0.05, delta = 0.5
     * Spike at index = floor(K / R), where R = c * ln(K / delta) * sqrt(K)
     * Binary search sampling over pre-computed CDF table (cached per K).
   - Chunk Selection: Selects `degree` distinct chunks in [0, K) using Mulberry32.
     Complement sampling is used when degree > K/2 for efficiency.
   - Payload Construction: 32-bit word XOR across the selected chunks.
   - Decoder: Incremental GF(2) Gaussian Elimination:
     * Maintains pivot bitmask (Uint32Array) and pivot payload for each chunk.
     * When incoming droplet arrives, reduces it against existing pivots.
     * If degree > 0 after reduction, becomes a new pivot row; rank increments.
     * If degree == 0, classified as redundant ('dependent') and dropped silently.
     * When rank == K, performs back-substitution once to reconstruct all chunks.

C. Pipeline Integrity (Spec §6.5, src/lib/pipeline.js):
   - prepareFile(bytes, chunkSize, sid):
     Computes CRC32 of raw bytes, deflates via pako.deflate, splits into K chunks,
     zero-pads the final chunk if necessary.
   - assembleFile(decoder):
     Concatenates reconstructed chunks, truncates to compressedLen, inflates via
     pako.inflate, verifies CRC32 of result. Throws on any mismatch.

D. Display Rasterization (Spec §6.7, src/lib/qrdraw.js):
   - Calculates integer device pixels per module:
     `devicePxPerModule = Math.floor(availableSquareDevicePx / totalModules)`
   - Pure function `renderCellRgba`: Renders QR module matrix into flat RGBA
     Uint8ClampedArray with 4-module quiet zone on all sides.
   - Prevents sub-pixel blurring, browser antialiasing, and CSS scaling distortion.

E. Quadrant Crop Receiver Geometry (Spec §6.8, src/lib/crop.js):
   - Identifies central square in camera frame: `min(width, height)`.
   - Divides into N×N quadrants (`paddingFraction = 0`).
   - Closed decision: Unpadded quadrant partition guarantees zero inter-cell
     overlap, preventing adjacent finder patterns from corrupting jsQR detection.
